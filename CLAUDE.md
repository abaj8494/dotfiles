# dotfiles — orientation for Claude

Personal dotfiles repo, managed with **GNU Stow**. Each top-level directory is a stow *package*; its internal tree mirrors the path from `$HOME` where files should land.

- Remote: `git@github.com:abaj8494/dotfiles.git`
- Default working branch: `macos`
- Platform: macOS (Darwin)

## Stow convention

```
~/dotfiles/<package>/<path-from-$HOME>/<file>   →   $HOME/<path-from-$HOME>/<file>
```

Examples already in the repo:

| Package       | Source in repo                                         | Symlink target                                  |
|---------------|--------------------------------------------------------|-------------------------------------------------|
| `tmux`        | `tmux/.config/tmux/tmux.conf`                          | `~/.config/tmux/tmux.conf`                      |
| `zsh`         | `zsh/.config/zsh/.zshrc`                               | `~/.config/zsh/.zshrc`                          |
| `nvim`        | `nvim/.config/nvim/init.lua`                           | `~/.config/nvim/init.lua`                       |
| `sesh`        | `sesh/.config/sesh/sesh.toml`                          | `~/.config/sesh/sesh.toml`                      |
| `television`  | `television/.config/television/config.toml`            | `~/.config/television/config.toml`              |
| `karabiner`   | `karabiner/.config/karabiner/karabiner.json`           | `~/.config/karabiner/karabiner.json`            |
| `sioyek`      | `sioyek/Library/Application Support/sioyek/…`          | `~/Library/Application Support/sioyek/…`        |
| `watchdog`    | `watchdog/Library/LaunchAgents/com.*.plist`            | `~/Library/LaunchAgents/com.*.plist`            |

Stow folds whole directories where possible — so `~/.config/tmux` is itself the symlink (not each individual file inside). If you later add unrelated files directly under `~/.config/tmux/`, they'd end up tracked in the repo; keep that in mind when extending a package.

## Operating on the repo

```bash
# install / re-link a package (idempotent)
cd ~/dotfiles && stow <package>

# remove symlinks for a package without touching the source tree
cd ~/dotfiles && stow -D <package>

# install every package in one shot
cd ~/dotfiles && stow */
```

When **adding** a config:

1. Create the package dir and mirror the target path. E.g. for a config that should live at `~/.config/foo/bar.toml`:
   ```bash
   mkdir -p ~/dotfiles/foo/.config/foo
   mv ~/.config/foo/bar.toml ~/dotfiles/foo/.config/foo/bar.toml
   cd ~/dotfiles && stow foo
   ```
2. Verify with `readlink ~/.config/foo` — should resolve into `~/dotfiles/foo/…`.

## Package notes

- **`sesh`** — [joshmedeski/sesh](https://github.com/joshmedeski/sesh) tmux session manager. `sesh.toml` declares named sessions and `[[wildcard]]` patterns; `[[window]]` blocks are named window presets reusable via `windows = [...]`. Helper scripts in `sesh/.config/sesh/scripts/` (e.g. `picker.sh`, `remarkable_prep.sh`, `startup.sh`, `monitoring_prep.sh`). `startup.sh` pre-creates the seven always-open sessions (monitoring, remarkable, flashcards, configs, Finances, jobsync, uni) — it runs from `tmux.conf` via `run-shell -b` after TPM, with a 3s delay to let continuum finish. The default `startup_command` is `nvim '+Telescope find_files'`.
  - **`startup_script` gotcha**: sesh honors `startup_script` only on `[[window]]` blocks, **not** on `[[session]]`. For multi-pane session layouts, set `startup_command` to the prep-script path — sesh send-keys that path into pane 0, the shell executes it, the script uses explicit `tmux -t SESSION:...` targets to split/send-keys, and send-keys queued at pane 0 fire after the script exits (so you can pre-type a command that runs in pane 0 once layout is built). See `monitoring_prep.sh` / `remarkable_prep.sh`.
- **`television`** — [alexpasmantier/television](https://github.com/alexpasmantier/television) fuzzy picker. Cables live at `television/.config/television/cable/*.toml` — each defines a `[source]` command, `[preview]`, `[keybindings]`, and `[actions.*]`. Custom cables here: `c-pick`, `dotfiles-pick`, `content-org`, `sesh`, `clip-pages`, `clip-files`, `tmux-sessions`.
- **`tmux`** — prefix is `C-a`. Key session bindings:
  - `Prefix+K` → gum popup sesh picker
  - `Prefix+T` → themed fzf-tmux sesh picker (calls `~/.config/sesh/scripts/picker.sh`)
  - `Prefix+C-t` → tv channel picker in a popup
  - `Prefix+C-l` → `sesh last` (jump to previously-attached sesh session)
  - `startup.sh` runs via `run-shell -b` after TPM (3s delay). Continuum auto-restore is **off** — only auto-save (every 5 min) is active. Manual restore: `Prefix+C-S-r` (Ctrl-Shift-R; rebound off the resurrect default `C-r`, which needs `extended-keys on`).
  - **Popup PATH gotcha**: `display-popup -E` runs commands under a stripped PATH (`~/.opencode/bin:/opt/homebrew/bin:/bin:/usr/bin`) — `~/.local/bin` is *not* included. Binaries installed there (e.g. `tv`) must be invoked by absolute path or wrapped, otherwise the popup snaps shut with a silent "command not found".
- **`zsh`** — oh-my-zsh + powerlevel10k. Note: the `z` plugin is loaded by oh-my-zsh, then `unalias z` + `eval "$(zoxide init zsh)"` replaces it with zoxide (while keeping `z` as the invocation). The old z database (`zsh/.config/zsh/.z`) was imported into zoxide via `zoxide import --from=z --merge`. Also: a `tmux()` shell function wraps the CLI so that bare `tmux` (no args, outside tmux) runs `tmux attach` first — this avoids spawning an unnamed `0` session alongside the pre-warmed sesh sessions. `tmux <args>` still passes through unchanged.
- **`watchdog`** — LaunchAgents only. Two agents:
  - `com.aayushbajaj.watchdog-serve.plist` — local watchdog dashboard server (port 9847) under launchd with `KeepAlive`. The `collect` agent (sampling every 5min) was set up outside this repo and lives as a plain file in `~/Library/LaunchAgents/com.aayushbajaj.system-health-monitor.plist`.
  - `com.aayushbajaj.daily-init.plist` — fires `scripts/daily-init.sh` at **00:00** daily to create today's org-roam daily (so it exists without the user pressing `C-c d d`). `StartCalendarInterval` fires the missed run on wake if asleep at midnight. Runs under **`/bin/zsh`** (not bash) because the script's instant-deploy step needs Full Disk Access, which launchd only grants to zsh and which propagates down the chain via shebang resolution. Load with `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.aayushbajaj.daily-init.plist`.
- **`clip`** — clipboard relay to `clip.abaj.ai`. The launchd agent `com.aayushbajaj.clip-sync` (stowed plist) runs `scripts/clip-sync.sh`, which polls the macOS pasteboard and `POST`s every **text-only** copy (skips file/image clips via `osascript clipboard info`) to `https://clip.abaj.ai/api/clip`. Any device fetches the latest copied string with `curl -H "X-Clip-Token: …" https://clip.abaj.ai/api/clip` (also supports `?key=…`, and conditional `If-Modified-Since` → `304`/`200` via the `Last-Modified`/`X-Clip-Time` response headers — that's the reMarkable's "paste only when server is newer" path).
  - **Token** lives at `~/.config/clipd/token` (chmod 600, **not** in the repo). The server keeps the matching copy at `/usr/local/openresty/nginx/conf/clip.token` (root:www-data 640). `aj`/`red` are *not* usable here — they're hardcoded client-side in clip's `index.html`, so they're public.
  - **Server side is off-repo** (lives on `abaj.ai`): the endpoint is a token-gated openresty Lua handler `/usr/local/openresty/nginx/conf/clip-api.lua`, wired via `location = /api/clip` in conf.d `07-clip.conf` (exact-match, handled in-nginx — **not** proxied to the Go clip container on `:21313`). Storage is a flat file `/var/lib/clipd/latest.txt` (+ `latest.ts`), deliberately outside `persistence/` so the Go app's `*.txt` page glob never picks it up. Deploy = edit the `.lua` + `nginx -s reload` (no docker rebuild).
  - **pbpaste needs UTF-8**: `clip-sync.sh` exports `LANG`/`LC_ALL=en_US.UTF-8` because launchd gives the agent no locale, and without it pbpaste transcodes non-ASCII to a legacy encoding.
- **`herdr`** — [herdr](https://herdr.dev) agent multiplexer, being trialled alongside tmux. `config.toml` is a line-by-line port of `tmux.conf` (every binding carries the tmux line it came from), and `scripts/` fills the gaps herdr's config language can't express. Note `~/.config/herdr/` holds runtime state (sockets, logs, `session.json`, `plugins.json`), so stow folds `config.toml`, `scripts/` and `plugins/aj` individually rather than the whole directory.
  - **The `herdr config check` trap.** Since 0.8.0 it exits 1 on `config: issues found` (0.7.5 always exited 0), so `&&` is safe again. What it still *cannot* see is a chord that collides with a herdr **default** — that reports ok and then the default silently loses at runtime. Only both-in-file collisions are reported. That's why the config spells out every displaced default (and sets `swap_pane_left/down/right = ""` to free `prefix+shift+h/j/l` for the tab-move commands). Also: a TOML *parse* error discards the whole config and falls back to defaults, so validate against a throwaway `HOME` (`HOME=/tmp/x herdr config check`) before reloading.
  - **Key syntax** — `prefix+K` is silently `prefix+shift+k`, not `prefix+k`. Named punctuation `minus comma period quote backtick semicolon slash space plus ampersand` is valid; `dot`, `apostrophe`, `equal`, `delete/home/end/pageup` are not (use the literal char where one exists). Triple chords (`prefix+ctrl+shift+r`) are fine. `1..9` ranges only work on `switch_tab`/`switch_workspace`/`focus_agent`. `copy_mode` and `swap_pane_*` are real actions but are missing from `herdr --default-config`.
  - **`[[keys.command]]` runs a shell**, not an argv split: `type = "shell"` is `/bin/sh -lc "<cmd>"` detached, `pane`/`popup` are `/bin/sh -c`. So arguments, quotes and pipes work — but PATH is bare, hence `scripts/_herdr.sh` exporting a full one. Custom commands also get `HERDR_ACTIVE_{WORKSPACE,TAB,PANE}_ID` / `HERDR_ACTIVE_PANE_CWD`; panes get `HERDR_{WORKSPACE,TAB,PANE}_ID`.
    - `type = "pane"` is **not** tmux's `split-window`: it places where it likes (a tab, not a split of the current pane), takes no direction, and the pane outlives the command. The block has exactly six fields — `key`, `type`, `command`, `description`, `width`, `height` (the last two popup-only) — there is no `placement`/`direction`/`close_on_exit`, so don't go looking. For tmux-style "split here, and die when the program quits", split over the API and type `<cmd>; exit` — herdr closes a pane whose process has exited. That's what `lf-split.sh` does for `prefix+l` / `prefix+L` / `prefix+C-l`.
    - One key per action, so tmux chords that duplicate an action (`%`/`"` alongside `s`/`-`, `{` alongside `C-o`) are custom commands calling `herdr pane split|swap` with `$HERDR_ACTIVE_PANE_ID`. `prefix+!` (break-pane) is `herdr pane move <id> --new-tab`, which has no `[keys]` action either.
  - **sesh integration** — sesh only speaks tmux (upstream's multiplexer-agnostic goal is still aspirational), so `scripts/sesh.sh` reimplements `sesh connect` over herdr's socket API. `sesh.toml` stays the source of truth: names/paths/`startup_command`/`windows` come from `sesh list -c -j`, and the parts sesh doesn't export (`[default_session]`, `[[window]] startup_script`, `[[wildcard]]` rules) are parsed out of the TOML with awk. Mapping is session→workspace, window→tab. `sesh.sh picker|gum|connect|last|startup|list|preview|kill`; `last` reads the history kept by the plugin's focus-event hook. The picker is bound to `prefix+K`, `prefix+V`, `prefix+C-k` and `prefix+C-v` — the ctrl variants matter because fingers hold ctrl through the roll after `C-a` (all the same fzf picker; the `gum` mode is kept for tmux-parity but is strictly worse). Live workspaces sort first and carry herdr's agent state as a coloured glyph — amber working, red wants-you, green idle — which is the one thing this picker knows that sesh's never could. Picker gotchas already paid for: the config/zoxide dedup is one awk pass, not a `sed`+`grep` fork per row (~560 forks on a 277-entry zoxide list, all of it popup startup lag); and `strip_icon` eats *all* spaces after the icon, because an agent-less workspace row degrades its status mark to a space and a single-space strip fed connect/preview a name with a leading blank — which is what made picking a live workspace silently do nothing.
    - **The picker's two post-pick paths are deliberately asymmetric** (`sesh.sh pick <name>`, split out from `cmd_picker` so it's testable without a tty). A *live* workspace is `workspace focus`, a 10ms socket call — done synchronously, ~45ms end to end. A *new* one costs ~2s, and profiling says essentially all of it is `herdr_wait_prompt` waiting for p10k to render before the startup command can be send-keys'd (`workspace create` itself is 24ms) — so that path is detached and the popup closes in ~48ms. Don't "simplify" by detaching both: the popup's process group is SIGKILLed the instant its foreground process exits, so a detached focus loses a race it looks like it should win.
    - **`nohup cmd &` does not detach here.** macOS ships no `setsid(1)`, and `nohup` only ignores SIGHUP — the child stays in the popup's process group and dies with it, typically before it can even open its log file (the tell: no log at all). `herdr_detach` in `_herdr.sh` does it properly: **double**-fork (a single fork leaves the child a process-group leader under `set -m`, and `setsid()` then fails EPERM), then hand the caller a completion signal over the inherited stdout pipe — command substitution blocks until the grandchild `dup2`s its log over fd 1, which happens only *after* `setsid()`. A FIFO handshake does not work in its place: the SIGCHLD from the first fork's parent exiting interrupts the read.
    - **tmux-native startup commands are intercepted.** `monitoring_prep.sh` / `remarkable_prep.sh` call `tmux send-keys`/`split-window` directly — run from a herdr pane they reach across and rearrange the *real* tmux server. `translate_startup()` greps the referenced script for a `tmux` invocation and substitutes `scripts/prep/<name>.sh` (herdr API ports of the same layouts), dropping the command if no port exists. The test inspects the file, not the command string, so `nvim tmux.conf` survives.
    - `herdr pane run` is **send-keys, not exec** — it types into the pane's interactive shell, so aliases/functions (`l`, `lc`) and `~` expansion work like under tmux. A fresh pane drops input typed before its shell starts reading, so `herdr_wait_prompt` polls `pane read` until a prompt renders. (`herdr pane wait-output` would be the right tool but its arg parsing is broken in 0.7.5 — every combination of `--pane`/`--match`/`--timeout` and the positional id is rejected as "unknown option".)
  - **resurrect/continuum** — herdr natively survives detach, and `session.json` rebuilds workspaces/tabs/panes after a server restart or reboot (the Homebrew agent `homebrew.mxcl.herdr.plist` restarts the server), but **each pane in that file carries only a cwd — programs do not come back**. `scripts/persist.py` adds the resurrect half: `save`/`restore`/`list`/`show` snapshots under `~/.config/herdr/snapshots/`, relaunching allow-listed programs (`DEFAULT_PROCESSES`, extendable via `~/.config/herdr/resurrect-processes`), `nvim -S` when the cwd has a `Session.vim`, and agent CLIs restored as a **typed-but-not-executed** `claude --continue` so a restore never spawns a fleet of agents. Continuum's timer is `com.aayushbajaj.herdr-snapshot.plist` (`save --auto` every 60s, 10-deep rotation); auto-restore is deliberately off, as in tmux.conf.
    - **Named sessions are separate servers.** `herdr --session NAME` runs its own server on `~/.config/herdr/sessions/NAME/herdr.sock` with its own workspaces and its own `session.json`; the Homebrew agent only restarts the *default* server. `persist.py` takes `--session NAME` (sets `HERDR_SOCKET_PATH` for both the CLI and `api.py`), and `save --all-sessions` walks every live socket — the snapshot plist passes it, so autosaves are `auto.json` plus `auto@NAME.json` per session. Before 2026-09-14 the timer silently covered only the default server while the real work lived in `uni`/`rpi`.
    - **Claude panes are pinned to their conversation.** Snapshots carry `resume = "claude … --resume <id>"`, not a bare `--continue` (which picks the same latest conversation for every agent sharing a cwd). The id comes from the command line when the pane was started with `--resume`, otherwise from matching the process start time against `~/.claude/session-env/<id>` (a directory created at session start) and preferring the id whose transcript sits under `~/.claude/projects/<cwd-slug>/`.
    - **Post-reboot procedure.** herdr rebuilds each session's workspaces from its `session.json` as bare shells (and `[session] resume_agents_on_restore` re-attaches claude panes via the installed hook), so a plain `restore` would skip everything as "already open". Use `persist.py --session NAME restore --name <snap> --into-live`: it matches workspaces by label, tabs by order, panes by tree order, types each saved program into its pane, and leaves alone any pane that is no longer a bare shell. Start the session first (`herdr --session NAME`, which spawns its server), then run it from any shell.
    - Layout fidelity comes from `layout.export`/`layout.apply`, which round-trip the whole split tree in one call. Neither has a CLI subcommand, so `scripts/api.py` speaks the socket protocol directly (line-delimited JSON on `$HERDR_SOCKET_PATH`). `layout.apply` with `tab_id` **replaces** that tab; with `workspace_id` + `tab_label` it creates one. Its pane nodes accept a `command`, but the server spawns those with `PATH=/usr/bin:/bin:/usr/sbin:/sbin` — Homebrew binaries aren't findable — which is the other reason programs go in via send-keys.
    - **`layout.apply` is destructive: it kills every existing pane in the target tab and spawns new ones** (pane ids change, running processes die), even where the submitted tree carries the old `pane_id`s. Only ever apply to a workspace/tab you just created — never to a live one to "add a pane". `pane.split` is the non-destructive primitive, and it takes no `command`.
    - `scripts/tab-move.sh` exists for the same reason: tmux's `swap-window -t ±1` has **no herdr keybinding** (`move_tab_*`/`swap_tab_*` are unknown config keys; the TUI only reorders by mouse drag), but `tab.move` is in the socket API.
  - **`plugins/aj/`** — a linked local plugin whose `[[startup]]` command pre-creates the always-open sesh workspaces once per server start, which is the hook tmux.conf gets from `run-shell -b … startup.sh`. Its `[[events]] on = "workspace.focused"` hook runs `scripts/focus-track.sh`, which keeps `.current-workspace`/`.last-workspace` so `sesh.sh last` (prefix+C-l, as in tmux.conf) can toggle back — tmux gets this from `switch-client -l`, herdr has no last-workspace action at all. Recording it on the *event* rather than inside `sesh.sh` is what makes it count every route: sidebar, picker, `prefix+(`/`)`, navigate mode, mouse. Also exposes `sesh-prewarm` / `snapshot-save` / `snapshot-restore` as plugin actions (`herdr plugin action invoke <id>`). Link with `herdr plugin link .` from the plugin dir — `plugin link <path>` as an argument is rejected, the path must come after the flags. The registry (`plugins.json`, `.plugins.lock`) is per-user and not in git.
  - **Image previews need `[experimental] kitty_graphics = true`** — herdr otherwise drops Kitty graphics escapes from panes ("pane graphics require experimental.kitty_graphics"), which kills lf's previewer (it shells out to `kitty +kitten icat`). This is the analogue of `set -g allow-passthrough` in tmux.conf. Two more conditions, both verifiable:
    - the **client must have reconnected** since the flag was enabled — it latches `kitty_graphics` once at process start, so `herdr server reload-config` flips the server but not an attached client, and panes created before the reattach never get graphics. `grep 'client connected' ~/.config/herdr/herdr-server.log` must show non-zero `cell_width_px`/`cell_height_px`; a zero there means "the client didn't have the flag", never "the terminal can't report pixels". Enablement is always: set flag → detach/reattach → **new pane**;
    - **herdr ≥ 0.8.0**. On 0.7.5 the client reported `cell_width_px=0` under kitty no matter what, so no placement was possible. 0.8.0 reports 13×24 here and adds `pane.graphics.{info,set,clear}` to the socket API — `api.py pane.graphics.info '{"pane_id":"…"}'` is the quickest check that a given pane can take images.
  - **lf image previews needed two fixes in the `lf` package, not in herdr.** With `kitty_graphics` on and a reconnected 0.8.0 client, `icat` works fine in a pane — but `lf/.config/lf/preview` gates image rendering on `TERM = xterm-kitty || $KITTY_WINDOW_ID`, and a herdr pane has neither (`TERM=xterm-256color`, and the server is launched by launchd so nothing kitty-ish is in its environment). tmux passes only because its server inherited `KITTY_WINDOW_ID` from kitty. The gate now also accepts `$HERDR_PANE_ID`; without it every image preview silently degraded to the pistol text fallback. Separately, `lf/.config/lf/clean` now calls `api.py pane.graphics.clear` when `$HERDR_PANE_ID` is set, because herdr doesn't reliably act on kitty's in-band "delete all images" escape and stale previews linger.
  - **The status bar is the tab row plus the sidebar.** herdr has no status *line* and no format string — no `status-left`/`status-right` equivalent. `[ui] tab_bar_position = "bottom"` + `hide_tab_bar_when_single_tab = false` puts the window list where tmux's status bar sits, and `[ui.sidebar.spaces] rows` carries the workspace name / branch / git status that tokyo-night-tmux shows. For tmux-style widgets (clock, battery) the hook is `workspace.report_metadata`, whose values render as `$name` tokens in those rows. The theme is deliberately **kanagawa**, not the tokyo-night of tmux.conf, and `scripts/sesh.sh`'s fzf palette matches it — the point is telling at a glance which multiplexer you're in.
  - **Ecosystem** (checked 2026-08-07, ~510 plugins at herdr.dev/plugins): `fullerzz/herdr-plugin-sesh` is a sesh-style picker that reads a subset of `sesh.toml` but needs herdr ≥ 0.8.0; `ntindle/herdr-resurrect` is the same idea as `persist.py`, with event-driven autosave. Both are alternatives to the scripts here, not complements — don't run two of them at once.
- **`daily-comic`** — LaunchAgent only (`com.aayushbajaj.daily-comic.plist`), ticking `scripts/daily-comic.sh` every 60s. Mails one not-yet-sent image per day from `~/lattice/3-resources/media/archive-gdrive/comics/one of those days` via `msmtp -a gmail`, body = one random emoji, at a uniformly random time of day. Every tick but one is a no-op: the script plans a time once per day (`~/.local/state/daily-comic/plan`), re-rolls inside the rest of the day if the slot was slept through by >30min (otherwise every mail would clump at lid-open), and records deliveries in `sent.log` — when the folder is exhausted it goes quiet. `--status` / `--test` (mails yourself, no state) / `--now`.
  - **Recipient is off-repo**: `~/.config/daily-comic/config` (`TO=…`, optional `BCC="…"`, chmod 600) — this repo is public. BCC addresses are added as msmtp envelope recipients only; no `Bcc:` header is ever written.
  - Depends on gpg-agent still holding the passphrase for `~/.authinfo.gpg` (7-day cache TTL); a failed send backs off 30min rather than raising a pinentry popup every minute.
  - **zsh gotcha paid for here**: `${$(<file)#* }` word-splits the file and strips per-word, yielding *both* fields; the resulting `bad math expression` doesn't abort the script, so the `(( NOW < AT )) && exit 0` guard fell through and the first tick sent immediately. Parse state files with `read -r a b < file`.
- **`nvim-archived-20251209/`** — snapshot of a previous nvim config, kept for reference; not meant to be stowed.
- **`stow-packages/`** — currently empty; placeholder.
- **`scripts/`** — standalone helper scripts, not a stow package per se. Referenced by absolute path (e.g. the `daily-init` LaunchAgent points at `scripts/daily-init.sh`).
  - **`daily-init.sh`** — midnight daily generator. Drives the live Emacs daemon via `(org-roam-dailies--capture (current-time) t)` (the goto path behind `C-c d d`, which runs `aj/daily-file-open-hook` for full setup), then invokes ferrari's `sync-daily.sh` (via **shebang**, never `bash <path>` — preserves the FDA responsible-process tag) for an instant reMarkable push instead of waiting for the next wake-watch tick. **Generates only when the org is absent** — re-running the goto on an existing daily would `save-buffer` and bump mtime, which the rmsync pipeline keys off (see `ferrari/CLAUDE.md` "Don't fire wake-watch on org-newer-than-pdf"). Socket discovery uses `getconf DARWIN_USER_TEMP_DIR` so it finds the daemon regardless of `$TMPDIR`.
  - **`clip-sync.sh`** — pasteboard poller behind the `clip` package's launchd agent (see the `clip` note above). Runs forever under `KeepAlive`; pushes text-only copies to `clip.abaj.ai`.

## Not managed by stow (intentionally)

- `~/.oh-my-zsh` (managed by omz itself)
- `~/powerlevel10k` (managed by its installer)
- tmux plugins under `~/.config/tmux/plugins/` (tpm manages them)
- neovim plugins (lazy.nvim manages them; only `lazy-lock.json` is committed)
- Homebrew, conda, nvm, bun, cargo, go — installed out-of-band; only their shell init lines live in `.zshrc`
- Secrets (`JOBSYNC_API_KEY`, etc.) — currently inlined in `.zshrc` and committed; **treat with care** when forking or sharing.

## Editing while stowed

Because paths like `~/.config/<pkg>` are symlinks into this repo, any edit through the symlinked path writes back to the repo. Editing `~/.config/tmux/tmux.conf` and editing `~/dotfiles/tmux/.config/tmux/tmux.conf` are the same operation.

## Commit hygiene

- Branch is `macos`; there's long-running WIP on it (emacs config evolution, sioyek keys, etc.) — treat pre-existing unstaged changes as the user's in-progress work and do **not** sweep them into unrelated commits.
- Commits should describe the *why* succinctly. No `Co-Authored-By` trailer (user preference).
